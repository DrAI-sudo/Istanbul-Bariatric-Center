---
name: Responsive image variants
description: How responsive srcset variants are generated and wired for public images
---

Responsive variants (480w/768w/1200w webp) for key public images are pre-generated by `node scripts/generate-image-variants.mjs` (uses sharp, dev dep). It writes `<name>-<width>w.webp` next to originals in client/public and a manifest at `client/src/data/image-variants.json`. Components build srcSet via `getSrcSet()` in `client/src/lib/image-variants.ts` (returns undefined if no manifest entry, falling back to plain src).

**Why:** Lighthouse flagged oversized images on mobile; runtime resizing isn't available on static hosting.

**How to apply:** When adding a new blog post cover or key image, re-run the script so variants + manifest stay in sync — otherwise the new image silently ships without srcset. Blog covers are auto-discovered from `image:` fields in blog-posts.ts; other images must be added to the script's `keyImages` list. No upscaling: widths ≥ original are skipped.
